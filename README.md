# ווצאפ ← מייל: מדריך מלא צעד אחר צעד (כולל הקמת שרת ודוקר מאפס)

המערכת מעבירה הודעות מקבוצת ווצאפ אחת או יותר למייל מרוכז (פעם ביום / פעם בשעה / על כל הודעה).
ליד כל הודעה כתוב מי שלח ומתי, ומדיה מופיעה כ־`[נשלחה תמונה]`, `[נשלחה הקלטה קולית]` וכדומה.

**הקוד מוכן. לא צריך לתכנת ולא צריך AI.** רק להעתיק פקודות לפי הסדר.

> ⏱️ זמן הקמה: בערך 30–45 דקות בפעם הראשונה.
> 💰 עלות: שרת וירטואלי בערך 5–10 דולר לחודש, **או חינם באורקל** (סעיף 2ב). כל השאר חינם.

## 0. מה זה בכלל שרת ודוקר?

- **שרת (VPS)** = מחשב שנמצא בחוות שרתים, דלוק 24/7 ומחובר לאינטרנט. שוכרים אותו בכמה דולרים לחודש ושולטים בו מרחוק דרך חלון פקודות. אין לו מסך ואין עכבר, רק פקודות.
- **Docker** = תוכנה שמריצה "קופסאות" (קונטיינרים). כל קופסה היא תוכנה מוכנה עם כל מה שהיא צריכה בפנים. לא צריך להתקין פייתון, כרום, ספריות וכו'. דוקר מוריד ומריץ הכול בפקודה אחת.
- **אצלנו יש 2 קופסאות:**
  1. **WAHA** – מחזיקה את הווצאפ מחובר (כמו ווצאפ ווב, אבל בשרת) ומודיעה על כל הודעה חדשה.
  2. **forwarder** – הקוד שלנו. מקבל את ההודעות, שומר אותן ושולח מייל מרוכז.

```
ווצאפ  ──►  WAHA  ──(כל הודעה נדחפת מיד)──►  forwarder  ──(פעם ביום)──►  📧 מייל
```

> ⚠️ **סיכון חסימה:** החיבור לווצאפ לא רשמי (דרך "מכשיר מקושר"). מספר שרק מקבל הודעות נמצא בסיכון נמוך, אבל הוא לא אפס. מומלץ להשתמש **במספר נוסף** ולצרף אותו לקבוצה.

## 1. הכנת סיסמת אפליקציה בגוגל

המערכת שולחת מיילים דרך חשבון ה-Gmail שלכם, אבל **לא** עם הסיסמה הרגילה. היא משתמשת ב"סיסמת אפליקציה" מיוחדת.

1. נכנסים ל-https://myaccount.google.com/security
2. מוודאים ש**אימות דו-שלבי** מופעל. אם לא, מפעילים אותו (צריך טלפון).
3. נכנסים ישירות ל-https://myaccount.google.com/apppasswords
   (אין לזה כפתור בתפריט! רק דרך הקישור או החיפוש בראש העמוד).
4. בשם האפליקציה כותבים משהו כמו `whatsapp-mail` ← **יצירה**.
5. מופיע קוד של 16 אותיות (למשל `abcd efgh ijkl mnop`). **מעתיקים ושומרים בצד.** הוא לא יוצג שוב.

## 2. שכירת שרת

יש שתי דרכים. בוחרים **אחת**:

| | 2א – Vultr (או ספק דומה) | 2ב – Oracle Cloud |
|---|---|---|
| מחיר | בערך 5–10 דולר לחודש | **חינם** (Always Free) |
| קושי | קל | בינוני: הרשמה מסובכת יותר, ולפעמים "אין מקום" |
| כרטיס אשראי | כן | כן (לאימות בלבד, לא מחויב) |
| סיכון | אין | אורקל עלולה לקחת בחזרה שרת "לא פעיל" (פרטים בהמשך) |

### 2א – Vultr

כל ספק VPS מתאים: Vultr, DigitalOcean, Hetzner, Contabo ועוד. הדוגמה כאן היא עם **Vultr**:

1. נרשמים ב-https://www.vultr.com ומוסיפים אמצעי תשלום.
2. לוחצים **Deploy** ← **Deploy New Server**.
3. בוחרים:
   - **Type:** Shared CPU (Cloud Compute)
   - **Location:** כל מיקום. אפשר Tel Aviv, אם יש, או אירופה (Frankfurt / Amsterdam)
   - **Image / OS:** **Ubuntu 24.04 LTS x64**
   - **Plan:** **לפחות 2GB RAM** (WAHA מריץ דפדפן כרום בפנים, ועם 1GB הוא עלול לקרוס)
4. לוחצים **Deploy Now** ומחכים 1–2 דקות, עד שהסטטוס יהיה **Running**.
5. נכנסים לשרת ברשימה ורושמים בצד:
   - **IP Address** (למשל `45.76.123.45`)
   - **Username:** `root`
   - **Password:** לוחצים על סמל העין או ההעתקה

### 2ב – Oracle Cloud (חינם)

אורקל נותנת בחינם לתמיד שרת **ARM** (מעבד Ampere) עם עד 2 ליבות ו-12GB זיכרון. זה יותר ממספיק.

**הרשמה:**
1. נכנסים ל-https://www.oracle.com/cloud/free ← **Start for free**
2. ממלאים פרטים, מאמתים מייל, ומכניסים כרטיס אשראי (לאימות בלבד. בחשבון Free לא מחייבים)
3. **Home Region:** בוחרים אזור קרוב (למשל **Israel Central (Jerusalem)** או **Germany Central (Frankfurt)**).
   ⚠️ **אי אפשר לשנות אותו אחר כך!** השרת החינמי חייב להיות באזור הזה.
4. ההרשמה יכולה לקחת כמה דקות עד שעות, עד שהחשבון מאושר.

**יצירת השרת:**
1. בתפריט ☰ ← **Compute** ← **Instances** ← **Create instance**
2. **Name:** למשל `whatsapp`
3. **Image and shape** ← **Edit**:
   - **Image:** **Canonical Ubuntu 24.04**
   - **Shape:** **Change shape** ← **Ampere** ← **VM.Standard.A1.Flex** ← **1 OCPU** ו-**6 GB** זיכרון (מספיק בהחלט)
   - מוודאים שמופיע הכיתוב **Always Free-eligible**
4. **Add SSH keys:** בוחרים **Generate a key pair for me** ← לוחצים **Save private key**.
   יורד קובץ כמו `ssh-key-2026-10-01.key`. **שומרים אותו! בלעדיו אי אפשר להיכנס לשרת.**
5. **Create** ← מחכים עד שהסטטוס **Running** ← מעתיקים את ה-**Public IP address**

> 💡 **שגיאת `Out of capacity` / `Out of host capacity`:** אין כרגע שרתים פנויים באזור. מנסים **Availability domain** אחר (באותו מסך), או מנסים שוב בעוד כמה שעות. זה נפוץ.

> ⚠️ **שרת "לא פעיל":** לפי התיעוד של אורקל, שרת חינמי שבמשך 7 ימים משתמש בפחות מ-20% מעבד, רשת וזיכרון **עלול להילקח בחזרה**. המערכת שלנו קלה מאוד, אז זה סיכון אמיתי. לפי דיווחי משתמשים, שדרוג החשבון ל-**Pay As You Go** (בתפריט Billing) מונע את זה, ואורקל עדיין לא גובה כסף על משאבי Always Free. כדאי לקרוא את התנאים לפני כן.

**ההבדלים בהמשך המדריך לאורקל:**
- **התחברות (שלב 3):** במקום סיסמה משתמשים בקובץ המפתח, והמשתמש הוא `ubuntu` ולא `root`:
  ```
  ssh -i "$HOME\Downloads\ssh-key-2026-10-01.key" ubuntu@IP-של-השרת
  ```
  אם מופיעה שגיאה `UNPROTECTED PRIVATE KEY FILE` / `bad permissions`, מריצים פעם אחת ב-PowerShell (עם שם הקובץ שלכם) ומנסים שוב:
  ```
  icacls "$HOME\Downloads\ssh-key-2026-10-01.key" /inheritance:r /grant:r "$($env:USERNAME):R"
  ```
- **אחרי שנכנסים לשרת:** מריצים `sudo -i` כדי להפוך ל-root. מכאן כל הפקודות זהות.
- **בקובץ `.env` (שלב 5.3):** משנים את השורה `WAHA_IMAGE=devlikeapro/waha:arm` (גרסה למעבדי ARM).
- **המנהרה (שלב 7):**
  ```
  ssh -i "$HOME\Downloads\ssh-key-2026-10-01.key" -L 3000:localhost:3000 ubuntu@IP-של-השרת
  ```

<a id="3"></a>
## 3. התחברות לשרת מהמחשב

ב-Windows 10/11 כבר מותקן כל מה שצריך.
> **באורקל** ההתחברות קצת שונה (עם קובץ מפתח). ראו "ההבדלים בהמשך המדריך לאורקל" בסוף סעיף 2ב.

> 🛡️ **משתמשי נטפרי:** החיבור לשרת (SSH, פורט 22) חסום כברירת מחדל. לפני ההתחברות שולחים לנטפרי בקשת פתיחה, עם כתובת ה-IP של השרת שלכם:
> **"שלום, אבקש לפתוח חיבור SSH (פורט 22) לשרת הפרטי שלי בכתובת IP: `45.76.123.45`. השרת משמש להרצת אוטומציה לשליחת מיילים ואין בו תוכן לגלישה. תודה."**

1. לוחצים על **התחל**, כותבים `PowerShell` ופותחים.
2. כותבים (עם ה-IP שלכם):
   ```
   ssh root@45.76.123.45
   ```
3. בפעם הראשונה תופיע שאלה `Are you sure you want to continue connecting?` ← כותבים `yes` ← Enter.
4. מבקשים סיסמה ← מדביקים את הסיסמה מ-Vultr עם **קליק ימני** ← Enter.
   > 💡 **בזמן הקלדת סיסמה לא רואים כלום על המסך, אפילו לא כוכביות.** זה תקין! פשוט מדביקים ולוחצים Enter.
5. אם רואים שורה שמסתיימת ב-`root@...:~#`, **אתם בתוך השרת.** 🎉

> מעכשיו, כל פקודה בהמשך מדביקים בחלון הזה (קליק ימני = הדבקה) ולוחצים Enter.

<a id="5"></a>
## 5. הורדת הקוד והגדרות

### 5.1 הורדת הקוד
```
git clone https://github.com/bot-sync-up/whatsapp-to-mail.git
cd whatsapp-to-mail
cp .env.example .env
```

### 5.2 יצירת מפתח אקראי
המפתח מגן על ה-WAHA שלכם. מריצים:
```
openssl rand -hex 16
```
יוצאת שורה כמו `3f9a1c...`. מעתיקים אותה: מסמנים עם העכבר, והסימון כבר מעתיק.

### 5.3 עריכת קובץ ההגדרות
```
nano .env
```
נפתח עורך טקסט פשוט. **אין עכבר. זזים עם החצים במקלדת.**

ממלאים:
| שורה | מה לשים |
|---|---|
| `WAHA_IMAGE=` | להשאיר כמו שזה. **רק באורקל:** `devlikeapro/waha:arm` |
| `WAHA_API_KEY=` | המפתח מסעיף 5.2 |
| `WAHA_DASHBOARD_PASSWORD=` | סיסמה שתבחרו לכניסה ללוח הבקרה |
| `GROUPS=` | **להשאיר ריק בינתיים!** (נמלא בשלב 8) |
| `MAIL_FROM=` | כתובת ה-Gmail ששולחת |
| `MAIL_APP_PASSWORD=` | 16 האותיות מסעיף 1 |
| `MAIL_TO=` | הכתובת של מי שמקבל. כמה כתובות מפרידים בפסיק |
| `SEND_MODE=` | `daily` (פעם ביום) / `hourly` (פעם בשעה) / `immediate` (על כל הודעה) |
| `DAILY_TIME=` | באיזו שעה לשלוח את הסיכום היומי, למשל `21:00` |

**שמירה ויציאה מ-nano:**
- `Ctrl+O` ← `Enter` (שמירה)
- `Ctrl+X` (יציאה)

## 6. הפעלה

```
docker compose up -d --build
```
בפעם הראשונה זה לוקח כמה דקות, כי דוקר מוריד את WAHA (בערך 1GB) ובונה את ה-forwarder.

```
docker compose ps
```
צריך לראות `waha` ו-`forwarder`, ושניהם במצב `Up` / `running`.

<a id="7"></a>
## 7. חיבור הווצאפ (סריקת QR)

מטעמי אבטחה לוח הבקרה של WAHA **לא פתוח לאינטרנט**. נכנסים אליו דרך "מנהרה" מאובטחת:

1. **במחשב שלכם** (לא בשרת!) פותחים **חלון PowerShell חדש** ומריצים:
   ```
   ssh -L 3000:localhost:3000 root@45.76.123.45
   ```
   מכניסים סיסמה. **משאירים את החלון הזה פתוח.**
2. פותחים בדפדפן במחשב: http://localhost:3000/dashboard
3. שם משתמש `admin`, והסיסמה מ-`WAHA_DASHBOARD_PASSWORD`.
4. אם הדשבורד מבקש **API Key**, מדביקים את המפתח מסעיף 5.2.
5. רואים סשן בשם **default** עם סטטוס **SCAN_QR_CODE**. לוחצים על סמל ה-QR / המצלמה.
6. **בטלפון:** ווצאפ ← ⋮ / הגדרות ← **מכשירים מקושרים** ← **קישור מכשיר** ← סורקים.
7. אחרי כמה שניות הסטטוס משתנה ל-**WORKING** ✅

עכשיו אפשר לסגור את חלון המנהרה. החיבור נשמר בשרת, גם אחרי הפעלה מחדש.

## 8. מציאת ה-ID של הקבוצה

לכל קבוצה בווצאפ יש מזהה ארוך כמו `120363012345678901@g.us`. כל עוד `GROUPS` ריק, ה-forwarder נמצא ב**מצב למידה** ומדפיס את המזהה של כל קבוצה שכותבים בה.

1. בחלון של השרת מריצים:
   ```
   docker compose logs -f forwarder
   ```
2. **שולחים הודעה כלשהי בקבוצה הרצויה** (מהטלפון).
3. בחלון תופיע שורה כמו:
   ```
   [מצב למידה] הודעה בקבוצה עם ID: 120363012345678901@g.us | שלום
   ```
4. מעתיקים את ה-ID ← לוחצים `Ctrl+C` כדי לצאת מהלוג.
5. עורכים שוב את ההגדרות:
   ```
   nano .env
   ```
   וממלאים את שורת `GROUPS` בפורמט `ID|שם לתצוגה`:
   ```
   GROUPS=120363012345678901@g.us|קבוצת השיעור
   ```
   כמה קבוצות מפרידים בפסיק:
   ```
   GROUPS=1203...01@g.us|השיעור,1203...02@g.us|המשפחה
   ```
   שמירה: `Ctrl+O` ← `Enter` ← `Ctrl+X`
6. מפעילים מחדש כדי שההגדרות ייקלטו:
   ```
   docker compose up -d
   ```

<a id="9"></a>
## 9. בדיקה

1. כדי לבדוק מהר, משנים זמנית ב-`.env` את `SEND_MODE=immediate` ← שומרים ← `docker compose up -d`
2. מסתכלים בלוג:
   ```
   docker compose logs -f forwarder
   ```
   צריך לראות: `מאזין לקבוצות: קבוצת השיעור | מצב שליחה: immediate`
3. שולחים הודעה בקבוצה. תוך פחות מחצי דקה יופיע בלוג:
   ```
   התקבלה הודעה מ-משה ב-קבוצת השיעור: ...
   נשלח מייל עם 1 הודעות
   ```
4. בודקים שהמייל הגיע (גם בספאם!). אם הוא בספאם, מסמנים "לא ספאם".
5. מחזירים ל-`SEND_MODE=daily` ← שומרים ← `docker compose up -d`

**זהו! 🎉 המערכת רצה לבד, והמחשב שלכם יכול להיות כבוי.**

## 10. פקודות שימושיות ותקלות נפוצות

> כל הפקודות מריצים מתוך התיקייה. אם התחברתם מחדש לשרת, קודם מריצים: `cd whatsapp-to-mail`

| מה רוצים | פקודה |
|---|---|
| לראות מה קורה עכשיו | `docker compose logs -f forwarder` (יציאה: `Ctrl+C`) |
| לראות לוג של WAHA | `docker compose logs --tail 50 waha` |
| אחרי שינוי ב-`.env` | `docker compose up -d` |
| לעצור הכול | `docker compose down` |
| להפעיל שוב | `docker compose up -d` |
| לעדכן לגרסה חדשה | `git pull && docker compose pull && docker compose up -d --build` |

### תקלות נפוצות

| תקלה | פתרון |
|---|---|
| בלוג: `שגיאה בשליחת המייל ... Username and Password not accepted` | סיסמת האפליקציה שגויה, או שהוזנה הסיסמה הרגילה. צריך ליצור חדשה (סעיף 1) |
| במצב למידה לא מופיע כלום | בודקים בדשבורד שהסטטוס **WORKING**. אם לא, סורקים QR שוב (סעיף 7) |
| הסשן התנתק אחרי כמה שבועות | הטלפון לא התחבר לאינטרנט 14 יום. פותחים בו ווצאפ, ואם צריך סורקים QR מחדש |
| `waha` כל הזמן מתאתחל / קורס | חסר זיכרון. משדרגים את השרת ל-2GB RAM או יותר |
| `ssh: connect to host ... timed out` | ה-IP שגוי או שהשרת כבוי. בודקים בלוח הבקרה של הספק |

### אבטחה
- לוח הבקרה של WAHA פתוח **רק** מתוך השרת (נכנסים דרך מנהרת SSH). אל תשנו את זה.
- הקובץ `.env` מכיל סיסמאות. **לא משתפים אותו ולא מעלים אותו לשום מקום.**
- מעבירים הודעות של אחרים למישהו מחוץ לקבוצה, ולכן כדאי לקבל את הסכמת הקבוצה או המנהל.

---

### איך זה עובד מבפנים (למי שמתעניין)
- WAHA מוגדר לדחוף כל הודעה (`message.any`, כולל הודעות שאתם שלחתם) לכתובת `http://forwarder:5000/webhook`.
- ה-forwarder (`forwarder/app.py`, פייתון רגיל בלי ספריות חיצוניות) שומר כל הודעה ב-SQLite לפי מזהה ייחודי, כך שאין כפילויות ואין איבוד הודעות. כל 20 שניות הוא בודק אם הגיע הזמן לשלוח.
- המייל נשלח רק אחרי שליחה מוצלחת מסומן "נשלח". אם השליחה נכשלה, ינסה שוב בסבב הבא.
- `DRY_RUN=true` ב-`.env` = לא שולח מייל באמת, רק מדפיס אותו בלוג. שימושי לבדיקות.
